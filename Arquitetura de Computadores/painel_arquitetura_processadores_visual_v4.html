Uma mesma máquina pode ser descrita por várias camadas ao mesmo tempo.

Essa figura mistura estrutura física, execução, organização do sistema, memória e tipo de processamento.

1. Estrutura física

Pergunta central: quantas unidades físicas de processamento existem e como elas estão organizadas.
CPU (Central Processing Unit) / Processador × Núcleo (core)parte–todo

CPU é o chip processador. Core é uma unidade de execução dentro desse chip.

CPU = o chipcore = um “mini-processador” interno
Multicore × Multiprocessadornão são sinônimos
2 CPUs físicas • sistema multiprocessado

Multicore significa vários núcleos numa mesma CPU. Multiprocessador significa várias CPUs físicas no sistema.

2. Componentes internos

Pergunta central: o que existe dentro do sistema computacional e da CPU.
Visão interna da CPUregistradores, ULA e controle

Registradores guardam dados muito próximos da execução. A ULA (Unidade Lógica e Aritmética) realiza operações. A unidade de controle coordena os passos da instrução.

Hierarquia de memóriavelocidade × capacidade

Quanto mais perto da execução, menor a capacidade e maior a velocidade. Quanto mais longe, maior a capacidade e maior a latência.

3. Unidades de execução

Pergunta central: o que o hardware executa e como ele lida com múltiplos fluxos.
Processo × Threadambiente × fluxo

Processo é um programa em execução com seu próprio espaço de memória. Thread é um fluxo de instruções dentro desse processo.

Multithreading × SMT (Simultaneous Multithreading)concorrência × simultaneidade
duas threads usam o mesmo núcleo ao mesmo tempo

Multithreading é trabalhar com várias threads. SMT é uma técnica de hardware em que um único núcleo executa instruções de mais de uma thread simultaneamente.

alternar ≠ simultâneoSMT: 1 core, 2 ou mais threads ativas
Hyper-Threading da Intel: exemplo de SMT2 threads lógicas, 1 núcleo físico
Uma CPU física → um núcleo com dois contextos de execução
Núcleo físico único
Thread lógica A
registradores e estado arquitetural
Thread lógica B
registradores e estado arquitetural
Recursos compartilhados: unidades de execução, caches e outros recursos internos
O sistema operacional enxerga dois processadores lógicos. Quando uma thread deixa recursos disponíveis, o núcleo pode avançar instruções da outra. Não equivale a possuir dois núcleos físicos.

Hyper-Threading Technology (HT) é o nome comercial usado pela Intel para uma implementação de Simultaneous Multithreading (SMT). Enquanto multicore acrescenta núcleos físicos, HT acrescenta contextos lógicos de execução dentro de um núcleo compatível.

4. Execução de instruções: pipeline e paralelismo interno

Pergunta central: como as instruções avançam dentro do processador.
Pipelineestágios em série
Pipeline clássico: instruções sobrepostas em estágios diferentes
Busca→Decodificação→Execução→Escrita
Ciclo 1 de 7
No primeiro ciclo, a instrução I1 ocupa o estágio de busca. Avance para observar a sobreposição.

No pipeline, várias instruções ficam sobrepostas em estágios diferentes. Isso aumenta a vazão, mesmo que a latência individual continue existindo.

Superpipeline × Superescalarmais estágios × mais emissão
Duas formas diferentes de aumentar a vazão

Superpipeline

Divide cada estágio em subestágios menores para permitir ciclos internos mais curtos.

Busca 1→Busca 2
Decod. 1→Decod. 2
Ciclo1a metade2a metadePróximo...I1Busca 1Busca 2Decod. 1Decod. 2I2—Busca 1Busca 2Decod. 1
Ideia: estágios mais finos e avanço mais frequente. Uma única linha de processamento é subdividida.

Superescalar

Várias unidades de execução podem executar instruções independentes em paralelo.

Entrada
I1I2I3
Unidade A
I1: soma
Unidade B
I2: lógica
Ciclo1234Unid. AI1I3I5I7Unid. BI2I4I6I8
Ideia: duas instruções independentes podem avançar no mesmo ciclo, em unidades diferentes.
Comparação: superpipeline divide o tempo e os estágios; superescalar duplica/amplia as vias de execução. Um processador pode combinar as duas técnicas. As grades são didáticas, não representam um modelo comercial específico.

Superpipeline aprofunda os estágios. Superescalar tenta emitir várias instruções por ciclo, usando múltiplas unidades funcionais.

ILP significa Instruction-Level Parallelism — paralelismo em nível de instrução.

5. Tipos de processamento

Pergunta central: como instruções e dados se relacionam no fluxo de execução.
Taxonomia de Flynnfluxo de instruções e dados
Multiple Instruction, Multiple Data
Single Instruction, Multiple Data

A taxonomia de Flynn não diz quantas CPUs existem. Ela classifica o padrão de fluxo entre instruções e dados.

Processamento vetorialprincipalmente ligado a SIMD
uma única instrução atua sobre vários elementos

Vetorial não é uma categoria separada de Flynn; ele se relaciona principalmente com SIMD.

6. Organização do sistema

Pergunta central: os processadores têm o mesmo papel ou papéis diferentes?
SMP (Symmetric Multiprocessing)mesmo sistema operacional
qualquer CPU pode receber trabalho do mesmo SO

No SMP, os processadores ou núcleos são tratados de forma equivalente. O mesmo sistema operacional distribui o trabalho entre eles.

AMP (Asymmetric Multiprocessing)papéis específicos
Tempo real / controle

No AMP, existe assimetria: cada processador pode ter uma função específica, em vez de todos compartilharem exatamente o mesmo papel.

7. Organização da memória e coerência de cache

Pergunta central: como os processadores acessam a memória e mantêm dados consistentes.
UMA × NUMAtempo de acesso à memória
local = mais rápido • remoto = mais lento

Em UMA, o tempo de acesso tende a ser uniforme. Em NUMA, o sistema ainda enxerga a memória como acessível, mas há diferença de latência entre acesso local e remoto.

Coerência de cacheconsistência entre cópias

Coerência de cache significa impedir que processadores diferentes trabalhem com cópias contraditórias do mesmo dado.

CC-NUMA significa Cache-Coherent Non-Uniform Memory Access: uma arquitetura NUMA com mecanismos de coerência de cache.

8. Interconexão

Pergunta central: como os componentes se comunicam fisicamente.
Barramento × Crossbarconexão CPU ↔ memória

Barramento é simples, mas pode virar gargalo. Crossbar é mais caro, porém permite acessos simultâneos entre múltiplos pontos.

Malha, toro e hipercubotopologias entre nós
mesh: grade; torus: malha com conexões de borda; hipercubo: rede multidimensional com vários caminhos curtos.

9. Arquitetura RISC × CISC

Pergunta central: como o conjunto de instruções é desenhado e como isso afeta execução e pipeline.
Definiçõesconceito-base
• decodificação tende a ser mais rica
• instruções podem fazer mais trabalho
• mais modos de endereçamento
Complex Instruction Set Computer

RISC simplifica as instruções e geralmente privilegia regularidade. CISC concentra mais trabalho em instruções mais poderosas.

Mesma ideia resolvida de formas diferentescomparação prática
Mais instruções, porém mais simples

No RISC, normalmente as operações sobre memória são separadas em load e store. No CISC, uma instrução pode combinar várias ações num único comando.

Resumo relâmpago

Pegadinhas de prova
  • Multicore não é a mesma coisa que multiprocessador.
  • SMT não é a mesma coisa que SMP.
  • Vetorial não é uma quinta classe de Flynn; ele se relaciona principalmente com SIMD.
  • NUMA não quer dizer memória inacessível — quer dizer latência diferente.
  • Coerência de cache não significa “cache sempre igual à RAM”.
  • RISC e CISC não significam automaticamente “um é melhor que o outro”; o foco é a filosofia do conjunto de instruções.
